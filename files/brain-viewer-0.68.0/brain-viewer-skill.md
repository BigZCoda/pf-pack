## Run it

```
python skills/brain-viewer/serve.py            # http://127.0.0.1:8765 = home (chat)  ·  /projects  ·  /people  ·  /mentee  ·  /canvases  ·  /requests  ·  /map  ·  /status  ·  /holons  ·  /agents
python skills/brain-viewer/serve.py --port 8770
```

Before restarting, kill every running `serve.py` (Windows lets two bind the same port and the stale one answers old routes).

Local only (127.0.0.1). No build step, no dependencies beyond Python. Ctrl+C stops it.

### Forge routing checks

`node --test skills/brain-viewer/forge-routing.test.js` checks the DOM-free geometry router.
With the viewer running, `python skills/brain-viewer/forge-browser-checks.py` runs the browser regression suite against `REPLIT_DEV_DOMAIN` (or pass `--base-url`). The Python project manifest supplies Playwright for tests only; the viewer still needs no third-party runtime packages. Browser checks intercept fixture saves in memory and never write test drawings into the brain.

The renderer uses `forge-routing.js` for multi-obstacle routes and updates existing paths during dragging. It preserves unobstructed curves and existing cross-cell owner semantics. A dashed line with a “route blocked” tooltip means no route was found within the bounded search or an endpoint overlaps an obstacle; it is not a claim that the fallback avoids obstacles.

## What it does

- **Reads** the ordered list in `skills/brain-viewer/mentee-content-manifest.json` (stage → pieces → path / kind / state / note), every markdown piece from the brain, every canvas piece as its nodes, and two live app pieces (`GET /checkin-templates` with the admin key, `GET /presets` with the personal token) through the server, so no token ever reaches the page.
- **Edits write to the real files.** The Edit → Save path overwrites the canonical markdown (line endings preserved) and appends a `MODIFIED` line to `context/log.md` as agent `brain-viewer`, so rounds and the night agent see every edit. Git is the undo.
- **Mark reviewed** writes a `reviewedAt` timestamp into the manifest, so the owner's pass over the mentee content is recorded, piece by piece.
- Only paths named in the manifest can be read or written. To add, reorder or retire a piece, edit the manifest.

## What it is not

Not a sync surface (it reads and writes the brain's own files on this machine). Not the app (the app pieces are read-only mirrors). Not the Living Tree. Not hosted; hosting is the vision doc's open question 1.

## Added in 0.68.0 (2026-10-06: Round 3b of the review, the floor)
- From [[deliverables/viewer-review-2026-10-06.md]] finding 8 as its addendum corrected it: one bedrock, not a fork; the gate strengthened by a check of what ships against the people cards and the ledger ids; the chat kept in. Re-read against [[brain-viewer-holon/brain-viewer-definition.md]] first.
- **The exclusive bind.** `ExclusiveServer` (a `ThreadingHTTPServer` with `allow_reuse_address = False` and, on Windows, `SO_EXCLUSIVEADDRUSE` set in `server_bind`) is the listener, bound in `main()` right after the brain check and before anything is written. A second server on a held port fails to bind and exits 3 with one line ("port N is held by another process"); `port_answers()` before it stays the friendly path (exit 0, nothing started). A socket bound with `SO_REUSEADDR`, as every viewer before this one did, is refused on the same port (WinError 10013).
- **The route table.** `do_GET`, `do_PUT` and `do_POST` are dispatchers over `ROUTE_ROWS` (verb, exact paths or a prefix, handler) in the order the old if-chain tested them; each branch is a method of `H` (`_get_*`, `_put_*`, `_post_*`), and a handler that runs off its end returns `_FALLTHROUGH` so the next matching route is tried, as the chain fell through. `route_handlers(verb, path)` looks exact paths up in a dict and prefixes by `startswith`. The page templating (the injected `BV_MODE` and `BV_OWNER` script, `look_head`) is `render_page(route)`. `GET /api/routes` serves the table as data (`route_list()`), so a drawing of what runs can be derived from what is served. 94 handlers: 66 GET, 5 PUT, 23 POST; every page, every redirect and every API route answered as before when checked against the 0.67.0 server.
- **Three parts in their own files.** `part_live.py` (the Forge's files and fields, the canvases, the live maps, part state), `part_chat.py` (the chat, its effort and sign-in, what a turn carries, sessions read back and adopted) and `part_studio.py` (the image studio and its refusal record). `load_part(name)` runs each in serve.py's own namespace at the point the code used to sit, so every name is still `serve.<name>` (tests that point `serve.BRAIN` at a scratch folder reach them; `derive_day.py` still calls `serve.live_binding()`); the hook's supervisor lookup still finds `serve.py --supervise`. serve.py went from 11,771 lines to about 9,800.
- **The cache and the status file.** `projects_api()` caches `projects_build()` by the registry's and every ledger's modification time and size, the day and the brain (`_PROJECTS_CACHE`); only `_servedAt` is new on a hit. `files_walk()` stats the tree through `files_stat_walk()` (scandir, no call per file) and reuses the rows when every path, time and size and the log index's key are the same (`_FILES_WALK`). `write_status()` writes counts and the keys something reads (`_generatedAt`, `_generatedBy`, one row per page with its route and counts, the process and the server); the prose paragraphs are gone.
- **The release path** (`release.py`). Every `*.test.py` (fifteen) and the node tests gate a release, each run with `BRAIN_ROOT` and the working folder an empty temp folder, with a timeout, and a guard compares the brain's files before and after (`brain_snapshot()`, `GUARD_IGNORE` for what a running viewer writes itself). `md.test.py` ends its node script with `process.exit(0)` and writes its two documents inline; `call.test.py`, `prep-v3.test.py` (a synthetic groups file, cards and subject files), `adapter.test.py` (a synthetic catalog and callers; its twin is written in the scratch brain), `home.test.py` (a temp mantra pool) and `thread.test.py` (the owner set by the test) read nothing in the real brain. The tests, `package.json` and `package-lock.json` stay out of the pack, and so does `day-manifest.json` (this brain's own day). A version with no heading on the what's-new page is refused (`whats_new_has()`). Two gate checks: `ledger_ids()`, a ledger id in a string a page shows (`shown_text()` blanks comments and docstrings in code; documents and data are read whole), and `people_names()`, every people card's title, its first word, and the owner's names from `viewer/settings.json`, anywhere in a shipped file. The first run found 114 (68 ids, 46 names); all fixed. The tools the viewer requires are reported, not stopped on. `--build-only` builds and gates into `pf-pack-staging/brain-viewer-<version>/` beside the pack (files/, updates/, manifest-rows.json) and stops before the pack, the manifest and any commit. `component.json` and this file's front matter carry the release version (`sync_skill_version()`).

## 0.59.0 conventions (2026-10-02, late)

- **No shipped file carries the owner's data or words.** The viewer is a pf-pack component that runs in mentee brains and the team copy, so nothing in skills/brain-viewer/ may hold a fact about this brain's owner (a date, a price, an event, a person) or quote the owner. Design reasons in comments are written in neutral words ("the owner asked on 9/21 that..."), never as a quotation. Found 10/02 when a fresh mentee brain's board showed this owner's milestone countdowns.
- **Owner facts live in files the widget reads.** The horizon widget reads `context/horizon.json` ({startedAt, milestones:[{at, label}]}); the flow ring reads `context/flow.json`; project labels and order, hidden people, the studio prompt file and negative prompt are keys in `viewer/settings.json` read through `BV.prefs()`. With no file a widget draws nothing fake and says so in one line.
- **The owner is `BV.owner`, never a name.** A face marked "me", a badge, a 403 message or a Reader reason says "the owner"; the ledger handle stays `@zak` only where it is the real handle on this brain's ledgers.
- **The release gate (`release.py`, `residue()`) fails on residue.** A quotation attributed to the owner, this brain's two milestone names (the gate lists them) outside context/ data files, a hard-coded 2026 date in a widget, or a path on this machine. Run `release.py --dry-run --notes ...` before any release; the gate's list is the fix list.
- **The notes marker in a prep is `<!-- Owner: ... -->`.** Older preps carry the earlier marker; nothing matches on it, so both stand.
