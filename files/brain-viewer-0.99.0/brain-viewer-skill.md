## Run it

```
python skills/brain-viewer/serve.py            # http://127.0.0.1:8765 = home (chat)  ·  /projects  ·  /people  ·  /mentee  ·  /canvases  ·  /requests  ·  /map  ·  /status  ·  /holons  ·  /agents
python skills/brain-viewer/serve.py --port 8770
```

Before restarting, kill every running `serve.py` (Windows lets two bind the same port and the stale one answers old routes).

Local only (127.0.0.1). No build step, no dependencies beyond Python. Ctrl+C stops it.

### Forge routing checks

`node --test skills/brain-viewer/forge-routing.test.js` checks the DOM-free geometry router.
With the viewer running, `python skills/brain-viewer/forge-browser-checks.py` runs the browser regression suite against `REPLIT_DEV_DOMAIN` (or pass `--base-url`). The Python project manifest supplies Playwright for tests only; the viewer still needs no third-party runtime packages. Browser checks intercept fixture saves in memory and never write test drawings into the brain.

The renderer uses `forge-routing.js` for multi-obstacle routes and updates existing paths during dragging. It preserves unobstructed curves and existing cross-cell owner semantics. A dashed line with a “route blocked” tooltip means no route was found within the bounded search or an endpoint overlaps an obstacle; it is not a claim that the fallback avoids obstacles.

## What it does

- **Reads** the ordered list in `skills/brain-viewer/mentee-content-manifest.json` (stage → pieces → path / kind / state / note), every markdown piece from the brain, every canvas piece as its nodes, and two live app pieces (`GET /checkin-templates` with the admin key, `GET /presets` with the personal token) through the server, so no token ever reaches the page.
- **Edits write to the real files.** The Edit → Save path overwrites the canonical markdown (line endings preserved) and appends a `MODIFIED` line to `context/log.md` as agent `brain-viewer`, so rounds and the night agent see every edit. Git is the undo.
- **Mark reviewed** writes a `reviewedAt` timestamp into the manifest, so the owner's pass over the mentee content is recorded, piece by piece.
- Only paths named in the manifest can be read or written. To add, reorder or retire a piece, edit the manifest.

## What it is not

Not a sync surface (it reads and writes the brain's own files on this machine). Not the app (the app pieces are read-only mirrors). Not the Living Tree. Not hosted; hosting is the vision doc's open question 1.

## 0.59.0 conventions (2026-10-02, late)

- **No shipped file carries the owner's data or words.** The viewer is a pf-pack component that runs in mentee brains and the team copy, so nothing in skills/brain-viewer/ may hold a fact about this brain's owner (a date, a price, an event, a person) or quote the owner. Design reasons in comments are written in neutral words ("the owner asked on 9/21 that..."), never as a quotation. Found 10/02 when a fresh mentee brain's board showed this owner's milestone countdowns.
- **Owner facts live in files the widget reads.** The horizon widget reads `context/horizon.json` ({startedAt, milestones:[{at, label}]}); the flow ring reads `context/flow.json`; project labels and order, hidden people, the studio prompt file and negative prompt are keys in `viewer/settings.json` read through `BV.prefs()`. With no file a widget draws nothing fake and says so in one line.
- **The owner is `BV.owner`, never a name.** A face marked "me", a badge, a 403 message or a Reader reason says "the owner"; the ledger handle stays `@zak` only where it is the real handle on this brain's ledgers.
- **The release gate (`release.py`, `residue()`) fails on residue.** A quotation attributed to the owner, this brain's two milestone names (the gate lists them) outside context/ data files, a hard-coded 2026 date in a widget, or a path on this machine. Run `release.py --dry-run --notes ...` before any release; the gate's list is the fix list.
- **The notes marker in a prep is `<!-- Owner: ... -->`.** Older preps carry the earlier marker; nothing matches on it, so both stand.
